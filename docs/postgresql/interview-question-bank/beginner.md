| BQ028 | What is an aggregate function? | A function reducing many input rows to a value per group/query, such as COUNT/SUM/AVG. | Aggregation changes result grain. | “A window function.” Windows retain rows. | Aggregate vs window? | 28 — Aggregate Functions |
| BQ029 | COUNT(*) vs COUNT(column)? | COUNT(*) counts rows; COUNT(column) counts non-null values. | NULL semantics make them different. | “They are always identical.” | Count only paid orders? | 28 — Aggregate Functions |

| BQ031 | WHERE vs HAVING? | WHERE filters rows before grouping; HAVING filters groups after grouping. | Predicate placement changes semantics and work. | “They are interchangeable.” | Where should status='paid' usually go? | 29 — GROUP BY and HAVING |

| BQ034 | What is a CROSS JOIN? | Cartesian product of every left row with every right row. | Row count multiplies unless one side is tiny. | “Join without duplicates.” | 100×50 rows yields how many? | 30 — Joins |
| BQ035 | What is a self join? | Joining a table to itself under different aliases/roles. | Useful for manager/employee or related-row comparisons. | “Recursive CTE only.” | Show employee-manager relation. | 30 — Joins |

| BQ037 | What is a subquery? | A query nested inside another SQL statement/expression. | It can return scalar, row, table, or existence information. | “Always slow.” | Correlated vs uncorrelated? | 31 — Subqueries |
| BQ038 | What does EXISTS mean? | TRUE if the subquery returns at least one row. | It expresses semi-join/existence intent without multiplication. | “Counts every matching row first.” | EXISTS vs JOIN? | 31 — Subqueries |
