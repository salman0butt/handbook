# React Handbook

A practical React handbook built to move from **fundamentals → real applications → advanced React → senior engineering**.

This is not intended to be a list of APIs to memorise. The goal is to understand how React behaves, why its APIs exist, how to choose between different approaches, and how to reason about production applications.

## Learning path

```text
React mental model
      ↓
JSX and rendering
      ↓
Components and props
      ↓
State and events
      ↓
Hooks
      ↓
Forms and routing
      ↓
Data fetching and server state
      ↓
TypeScript
      ↓
Testing and accessibility
      ↓
Performance
      ↓
Architecture and design patterns
      ↓
React internals
      ↓
Senior engineering decisions
```

## What this handbook will cover

### Foundation

- What React is and what problem it solves
- Declarative UI and the component model
- JSX, elements, components, props, state, and events
- Rendering lists and conditional interfaces

### Application development

- Hooks and custom hooks
- Forms and validation
- Routing
- API integration
- Client state and server state
- Error and loading states

### Production React

- TypeScript
- Testing
- Accessibility
- Authentication and frontend security
- Performance profiling and optimisation
- Project structure and feature architecture

### Advanced and senior topics

- Composition and reusable API design
- State ownership and component boundaries
- Rendering behaviour and reconciliation
- Suspense and concurrent rendering
- React Fiber and the render/commit phases
- Design systems and large frontend codebases
- Architecture trade-offs and engineering decisions

## How to study each topic

Most chapters follow the same pattern:

1. **What is it?** — establish the mental model.
2. **Why does it exist?** — understand the problem being solved.
3. **Basic example** — learn the smallest useful form.
4. **How it works** — go below the syntax.
5. **Common mistakes** — understand failure modes.
6. **Production approach** — see how the concept changes at scale.
7. **Trade-offs** — learn when *not* to use an approach.
8. **Exercise** — practise the idea instead of only reading it.

:::tip The goal
Don't aim to remember every React API. Aim to understand React well enough that unfamiliar APIs make sense when you encounter them.
:::
