# Node.js Interview Question Bank — 320 Questions

This bank contains **320 numbered questions** spanning Node basics through staff-level architecture, coding/output reasoning, misconceptions, and system design. Use the [Interview Questions → Study Chapters](/docs/nodejs/interview-question-bank/study-map) map to jump from any question range back to the runtime/backend chapters that support a strong answer.

| Range | Focus |
|---|---|
| Q001–Q064 | Node basics, runtime, process, globals, modules, npm, event loop, async, buffers |
| Q065–Q128 | streams, files, events, HTTP/TLS/fetch, networking, DNS, processes, workers, memory, V8, errors |
| Q129–Q192 | logging, config, validation, REST/frameworks, databases, Redis, queues, messaging, WebSockets, auth, security, crypto |
| Q193–Q256 | testing, test runner, TypeScript, CLI, diagnostics, performance, observability, shutdown, resilience, concurrency, serverless, Docker/K8s/CI, internals, hardening |
| Q257–Q320 | distributed systems, architecture, domain modeling, microservices, modular monoliths, scaling, incidents, anti-patterns, senior/staff design, coding/output/system design |

## How to answer

For important questions use:

```text
Question
  ↓
Expected answer
  ↓
Senior answer
  ↓
Weak answer to avoid
  ↓
Follow-up
```

Then connect the answer to a chapter or project you can discuss concretely.

## Scoring yourself

- **0:** incorrect / slogan only
- **1:** definition with missing mechanism
- **2:** correct mechanism + example
- **3:** mechanism + trade-off + production failure mode
- **4:** senior/staff answer with evidence, capacity/security/evolution implications

A strong interview-prep target is 3+ on core runtime, streams, HTTP, security, testing, diagnostics, resilience, and architecture questions.
