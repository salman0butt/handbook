# Version Baseline — July 31, 2026

> **Production baseline:** React Native **0.86.x**. React Native 0.87 has been branch-cut but is scheduled for stable release on August 10, 2026, so this handbook does not teach 0.87 behavior as current production behavior.

This page is the compatibility anchor for the rest of the handbook. When a blog post or library guide disagrees with this baseline, check whether it targets a different React Native minor.

## Architecture status

React Native 0.86 must not be explained using the old “JS thread → Bridge → native thread” diagram as if that were the runtime architecture. That model is useful only for old applications.

```text
React 19.2.3
    ↓
React Native 0.86
    ├─ Fabric renderer + Yoga
    ├─ TurboModules
    ├─ Codegen
    ├─ JSI / C++ runtime interfaces
    └─ Hermes V1
          ↓
Android native runtime / iOS native runtime
```

The 0.86 CocoaPods scripts explicitly configure New Architecture, set Fabric enabled, enable Hermes V1 by default, and default to removing legacy-architecture code. Attempts to disable the New Architecture are warned as unsupported since 0.82.

## Release and support policy

React Native ships a new minor roughly every two months. The project commits to maintaining the latest three minor series at varying support levels. On July 31, 2026, 0.86 and 0.85 are active, 0.84 is end-of-cycle, and 0.83 and older are unsupported. The 0.87 stable release is scheduled for **August 10, 2026**.

```text
0.87  future / RC line → scheduled Aug 10, 2026
0.86  latest stable    → production baseline here
0.85  active
0.84  end of cycle
0.83  unsupported
```

## Community CLI compatibility warning

The Community CLI has its own semver and release cycle. The 0.86 Community Template pins CLI 20.1.0 while npm currently exposes 20.2.0 as latest. The public compatibility table has historically lagged new React Native releases and currently lists CLI 20.x through React Native 0.85. Therefore:

1. use the official React Native release command for initializing the current latest project;
2. inside an existing 0.86 project, prefer the CLI versions generated by the official template;
3. do not add a global `react-native-cli` installation;
4. do not blindly override all `@react-native-community/cli*` packages to `latest` in an existing project.
