# Q001–Q070 — Beginner JavaScript Foundations

## Syntax, language and runtime

**Q001. What is JavaScript?** — **Expected:** A general-purpose language whose standardized core is ECMAScript; runtimes embed an engine and host APIs. **Reasoning:** Separate language from browser/Node. **Common incorrect:** “JavaScript is the DOM language.” **Follow-up:** Who defines ECMAScript? **Related:** [Start Here](../00-start-here.md).

**Q002. ECMAScript vs JavaScript?** — **Expected:** ECMA-262 defines the standardized language; JavaScript refers to implementations/ecosystems using it plus host capabilities. **Reasoning:** Standards ownership matters. **Common incorrect:** “They are two competing languages.” **Follow-up:** Where does `fetch` belong? **Related:** [Start Here](../00-start-here.md).

**Q003. Is JavaScript the same as Java?** — **Expected:** No; they are different languages/runtime models despite historical naming. **Reasoning:** Compare prototype/dynamic JS with Java's distinct type/runtime model. **Common incorrect:** “JavaScript is interpreted Java.” **Follow-up:** Name one JS-specific object model feature. **Related:** [Start Here](../00-start-here.md).

**Q004. Is `console.log` part of ECMAScript?** — **Expected:** No; `console` is supplied by hosts/devtools environments. **Reasoning:** ECMA-262 does not define the browser console API. **Common incorrect:** “Yes, because every browser has it.” **Follow-up:** Give three true ECMAScript built-ins. **Related:** [Start Here](../00-start-here.md).

**Q005. Script vs module code?** — **Expected:** Modules are strict, module-scoped, support import/export, have top-level `this` undefined, and participate in module linking/evaluation. **Reasoning:** Code kind changes semantics. **Common incorrect:** “Modules are only files with imports.” **Follow-up:** Can modules use top-level await? **Related:** [Modules](../36-modules.md).

**Q006. What does strict mode do?** — **Expected:** It applies stricter semantics/restrictions, turning some silent legacy behaviors into errors and changing some call/global behavior. **Reasoning:** It is a language mode, not a linter. **Common incorrect:** “It makes JavaScript statically typed.” **Follow-up:** Are modules strict automatically? **Related:** [Fundamentals](../01-fundamentals.md).

**Q007. What is an expression?** — **Expected:** Syntax that evaluates to a value (possibly with side effects). **Reasoning:** Distinguish evaluation from statement control. **Common incorrect:** “Any line ending in semicolon.” **Follow-up:** Is `x = 1` an expression? **Related:** [Fundamentals](../01-fundamentals.md).

**Q008. What is a statement?** — **Expected:** A syntactic unit controlling execution/declaration, such as `if`, block, loop, return, or expression statement. **Reasoning:** Statements need not produce usable expression values. **Common incorrect:** “A variable.” **Follow-up:** Why can't `if` appear everywhere an expression can? **Related:** [Fundamentals](../01-fundamentals.md).

**Q009. What is ASI?** — **Expected:** Automatic Semicolon Insertion is grammar-defined semicolon insertion in certain parse/restricted-production situations. **Reasoning:** It is not “semicolon at every newline.” **Common incorrect:** “JavaScript ignores semicolons.” **Follow-up:** What happens with `return` followed by a newline? **Related:** [Fundamentals](../01-fundamentals.md).

**Q010. Why can `return\n{ok:true}` return undefined?** — **Expected:** `return` has a LineTerminator restriction, so ASI terminates the return before the object literal. **Reasoning:** Parse/ASI rules, not runtime coercion. **Common incorrect:** “Object literals cannot be returned.” **Follow-up:** How would you format it safely? **Related:** [Fundamentals](../01-fundamentals.md).

## Variables, scope, hoisting and TDZ

**Q011. `let` vs `const`?** — **Expected:** Both are block-scoped lexical bindings; `const` requires initialization and prevents reassignment. **Reasoning:** Binding immutability is separate from object mutation. **Common incorrect:** “`const` makes objects immutable.” **Follow-up:** Can a const array be pushed to? **Related:** [Variables](../02-variables-and-declarations.md).

**Q012. `var` vs `let`?** — **Expected:** `var` is function/global scoped, initialized to `undefined` during instantiation, and has legacy redeclaration/global behavior; `let` is lexical/block scoped and uninitialized until its declaration executes. **Reasoning:** Scope + initialization. **Common incorrect:** “Only syntax differs.” **Follow-up:** How do loop closures differ? **Related:** [Variables](../02-variables-and-declarations.md).

**Q013. Is `let` hoisted?** — **Expected:** The lexical binding is created before execution reaches the declaration but remains uninitialized, producing the TDZ. **Reasoning:** “Not hoisted” hides real semantics. **Common incorrect:** “The binding does not exist before the line.” **Follow-up:** What error occurs on access? **Related:** [Variables](../02-variables-and-declarations.md).

**Q014. What is the TDZ?** — **Expected:** The period after a lexical binding is created but before it is initialized, during which access throws `ReferenceError`. **Reasoning:** Created ≠ initialized. **Common incorrect:** “Time before parsing.” **Follow-up:** Do classes have similar lexical initialization behavior? **Related:** [Variables](../02-variables-and-declarations.md).

**Q015. Declaration vs initialization vs assignment?** — **Expected:** Declaration introduces binding; initialization gives first value; assignment changes an initialized binding. **Reasoning:** Explains TDZ and const. **Common incorrect:** “All are the same operation.” **Follow-up:** Which step does `const x = 1` combine? **Related:** [Variables](../02-variables-and-declarations.md).

**Q016. What is block scope?** — **Expected:** A lexical binding's visibility is limited to a block such as `{}` containing its declaration. **Reasoning:** `let`/`const` use lexical environments. **Common incorrect:** “All variables in braces are function scoped.” **Follow-up:** Does `var` respect block scope? **Related:** [Variables](../02-variables-and-declarations.md).

**Q017. What is shadowing?** — **Expected:** An inner scope declares a binding with the same name, hiding the outer binding during name resolution. **Reasoning:** New binding, not mutation. **Common incorrect:** “The outer variable gets replaced.” **Follow-up:** What happens after leaving the block? **Related:** [Variables](../02-variables-and-declarations.md).

**Q018. What is global scope?** — **Expected:** Top-level environment associated with script/module/host semantics; browser classic script globals differ from module bindings. **Reasoning:** “Global” is code-kind dependent. **Common incorrect:** “Every top-level variable is `window` property.” **Follow-up:** Is top-level `let` on `window`? **Related:** [Variables](../02-variables-and-declarations.md).

**Q019. What is `globalThis`?** — **Expected:** Standardized access to the global `this` value across environments. **Reasoning:** Avoid host-specific `window`/`global` assumptions. **Common incorrect:** “A copy of all globals.” **Follow-up:** Does it make top-level module bindings properties? **Related:** [Variables](../02-variables-and-declarations.md).

**Q020. Output: `console.log(x); var x=1`?** — **Expected:** `undefined` in ordinary function/script context because the var binding is initialized to `undefined` before the assignment executes. **Reasoning:** Declaration instantiation. **Common incorrect:** “ReferenceError because declaration is later.” **Follow-up:** What changes with `let`? **Related:** [Variables](../02-variables-and-declarations.md).

## Types and values

**Q021. Name JavaScript primitive types.** — **Expected:** Undefined, Null, Boolean, String, Symbol, Number, BigInt. **Reasoning:** Object is the non-primitive language type. **Common incorrect:** “Array and function are primitives.” **Follow-up:** What type category are functions? **Related:** [Types](../03-types.md).

**Q022. Are functions objects?** — **Expected:** Yes, callable objects; some are also constructible. **Reasoning:** They have object identity/properties plus internal call behavior. **Common incorrect:** “Function is a primitive because typeof says function.” **Follow-up:** Are arrows constructible? **Related:** [Functions](../09-functions.md).

**Q023. Why is `typeof null` `'object'`?** — **Expected:** Historical compatibility behavior explicitly preserved by `typeof`; null is still a primitive. **Reasoning:** Operator result is not language-type definition. **Common incorrect:** “Null is an object.” **Follow-up:** How should you check null? **Related:** [Semantics cases](../92-97-ecmascript-history-specification.md#97--language-semantics-case-studies).

**Q024. `typeof []`?** — **Expected:** `'object'`; arrays are objects. **Reasoning:** `typeof` is broad, not array-specific. **Common incorrect:** `'array'`. **Follow-up:** Correct array test? **Related:** [Arrays](../18-arrays.md).

**Q025. Primitive vs object mental model?** — **Expected:** Primitives are immutable values; objects have identity and usually mutable state/properties. Bindings hold values in both cases. **Reasoning:** Avoid “objects stored by reference” oversimplification. **Common incorrect:** “Objects are variables that live on the heap by language guarantee.” **Follow-up:** What gets copied on assignment? **Related:** [Types](../03-types.md).

**Q026. What does assigning an object to another variable do?** — **Expected:** Copies the object value/reference identity so both bindings designate the same object. **Reasoning:** No deep clone occurs. **Common incorrect:** “Copies all properties.” **Follow-up:** How would spread differ? **Related:** [Types](../03-types.md).

**Q027. Mutability vs reassignment?** — **Expected:** Mutation changes object state; reassignment changes what value a binding holds. **Reasoning:** Explains const objects. **Common incorrect:** “They are identical.” **Follow-up:** Can primitives be mutated? **Related:** [Types](../03-types.md).

**Q028. What is object identity?** — **Expected:** Distinct objects are unequal by identity even if properties look identical; aliases to the same object share identity. **Reasoning:** Equality of objects is identity-based. **Common incorrect:** “Objects compare structurally with `===`.” **Follow-up:** `{a:1} === {a:1}`? **Related:** [Types](../03-types.md).

**Q029. What does `instanceof` check?** — **Expected:** Usually whether the constructor's prototype appears in the object's prototype chain, subject to `Symbol.hasInstance`. **Reasoning:** It is not general type metadata. **Common incorrect:** “Checks object class name string.” **Follow-up:** Why can cross-realm arrays fail it? **Related:** [Types](../03-types.md).

**Q030. Why prefer `Array.isArray` over `instanceof Array` for arrays?** — **Expected:** It performs an array brand check that works across realms; `instanceof` depends on prototype identity of a realm's constructor. **Reasoning:** Realms have distinct intrinsics. **Common incorrect:** “It is only faster.” **Follow-up:** What creates a second realm in a browser? **Related:** [Realms](../internals-performance-debugging.md#67--realms-and-global-objects).

## Coercion and equality

**Q031. What is implicit coercion?** — **Expected:** Language semantics automatically convert operands/values when an operation requires another type. **Reasoning:** It follows specified abstract operations. **Common incorrect:** “Random conversion by the engine.” **Follow-up:** Give an explicit conversion example. **Related:** [Coercion](../04-coercion.md).

**Q032. What values are falsy?** — **Expected:** undefined, null, false, +0/-0, 0n, NaN, and empty string. **Reasoning:** Objects are generally truthy. **Common incorrect:** “Empty arrays/objects are falsy.” **Follow-up:** `Boolean([])`? **Related:** [Coercion](../04-coercion.md).

**Q033. `Boolean([])`?** — **Expected:** `true`; arrays are objects and objects are truthy. **Reasoning:** Do not infer from “empty.” **Common incorrect:** `false`. **Follow-up:** `[] == false`? **Related:** [Coercion](../04-coercion.md).

**Q034. Why is `[] == false` true?** — **Expected:** Abstract equality converts false→0, array→`''`, then `''`→0, so 0 equals 0. **Reasoning:** Trace ToPrimitive/ToNumber. **Common incorrect:** “Empty arrays are falsy.” **Follow-up:** Is `Boolean([])` false? **Related:** [Coercion](../04-coercion.md).

**Q035. `null == undefined`?** — **Expected:** `true` by a specific abstract-equality rule. **Reasoning:** Not general falsy equality. **Common incorrect:** “Both become zero.” **Follow-up:** `null == 0`? **Related:** [Equality](../05-equality-and-comparison.md).

**Q036. `null === undefined`?** — **Expected:** `false`; strict equality sees different language types. **Reasoning:** No coercion. **Common incorrect:** `true` because both mean missing. **Follow-up:** When might `x == null` be deliberately used? **Related:** [Equality](../05-equality-and-comparison.md).

**Q037. Why is `NaN === NaN` false?** — **Expected:** Strict equality defines NaN unequal to every Number including itself. **Reasoning:** IEEE/ECMAScript numeric semantics. **Common incorrect:** “NaN is not a value.” **Follow-up:** Which check treats NaN as same? **Related:** [Equality](../05-equality-and-comparison.md).

**Q038. `Object.is(NaN, NaN)`?** — **Expected:** `true`; Object.is exposes SameValue semantics. **Reasoning:** SameValue differs from strict equality for NaN and signed zero. **Common incorrect:** `false` because NaN never equals itself. **Follow-up:** `Object.is(0,-0)`? **Related:** [Equality](../05-equality-and-comparison.md).

**Q039. `0 === -0` vs `Object.is(0,-0)`?** — **Expected:** Strict equality is true; Object.is is false. **Reasoning:** Strict Equality treats signed zeros equal; SameValue distinguishes. **Common incorrect:** “Both false.” **Follow-up:** What equality does Set use? **Related:** [Equality](../05-equality-and-comparison.md).

**Q040. Why does `[NaN].includes(NaN)` return true?** — **Expected:** `includes` uses SameValueZero, where NaN matches NaN. **Reasoning:** Standard APIs use different equality algorithms. **Common incorrect:** “Arrays special-case NaN ad hoc.” **Follow-up:** What does `indexOf(NaN)` return? **Related:** [Equality](../05-equality-and-comparison.md).

## Operators and control flow

**Q041. Difference between `||` and `??`?** — **Expected:** `||` falls back on any falsy value; `??` only on null/undefined. **Reasoning:** Preserve valid 0/false/empty string. **Common incorrect:** “They are aliases.” **Follow-up:** Evaluate `0 || 5` and `0 ?? 5`. **Related:** [Operators](../06-08-operators-control-iteration.md).

**Q042. What does `&&` return?** — **Expected:** One operand: first falsy, otherwise last evaluated operand. **Reasoning:** It short-circuits and is not boolean-only. **Common incorrect:** “Always true or false.” **Follow-up:** What does `'x' && 10` return? **Related:** [Operators](../06-08-operators-control-iteration.md).

**Q043. What does optional chaining short-circuit on?** — **Expected:** `null` or `undefined` at an optional chain step. **Reasoning:** It does not swallow all errors/falsy values. **Common incorrect:** “Any falsy value.” **Follow-up:** Does it catch getter exceptions? **Related:** [Advanced APIs](../37-47-advanced-language-apis.md#45--optional-chaining-and-nullish-coalescing).

**Q044. Why can `(obj?.a).b` throw?** — **Expected:** Grouping ends the continuous optional chain; `.b` is then ordinary access on possibly undefined. **Reasoning:** Grammar/evaluation chain boundary. **Common incorrect:** “Parentheses are ignored.” **Follow-up:** Safe form? **Related:** [Advanced APIs](../37-47-advanced-language-apis.md#45--optional-chaining-and-nullish-coalescing).

**Q045. What does `typeof undeclaredName` return?** — **Expected:** `'undefined'` for an unresolvable identifier in this special operator case. **Reasoning:** `typeof` has special unresolvable-reference handling. **Common incorrect:** “Always ReferenceError.” **Follow-up:** What about a TDZ lexical binding? **Related:** [Operators](../06-08-operators-control-iteration.md).

**Q046. What does `in` test?** — **Expected:** Whether a property key exists as own or inherited property on an object. **Reasoning:** Different from Object.hasOwn. **Common incorrect:** “Only own enumerable properties.” **Follow-up:** Own-only alternative? **Related:** [Objects](../12-15-objects-and-descriptors.md).

**Q047. What does `delete` do?** — **Expected:** Attempts to remove an object property according to configurability; it does not delete lexical variables. **Reasoning:** Property operation, not variable cleanup. **Common incorrect:** “Frees memory immediately.” **Follow-up:** What determines GC? **Related:** [Objects](../12-15-objects-and-descriptors.md).

**Q048. Ternary operator purpose?** — **Expected:** Conditional expression choosing one of two expressions and producing a value. **Reasoning:** Unlike `if`, it is an expression. **Common incorrect:** “A loop shorthand.” **Follow-up:** When does nesting hurt readability? **Related:** [Operators](../06-08-operators-control-iteration.md).

**Q049. Can `finally` change a returned value?** — **Expected:** Yes; an abrupt completion like `return` in finally can replace the earlier return/throw. **Reasoning:** Completion propagation. **Common incorrect:** “Finally is observation-only.” **Follow-up:** Why avoid returning from finally? **Related:** [Control flow](../06-08-operators-control-iteration.md).

**Q050. Difference between `throw` and `return`?** — **Expected:** Both are abrupt completions, but return completes a function normally with a value while throw propagates an exception until handled. **Reasoning:** Different completion types. **Common incorrect:** “Throw only logs an error.” **Follow-up:** What does finally do during either? **Related:** [Control flow](../06-08-operators-control-iteration.md).

## Loops and iteration

**Q051. `for...of` vs `for...in`?** — **Expected:** for-of consumes iterable values; for-in enumerates enumerable string property keys including inherited ones. **Reasoning:** Protocol vs property enumeration. **Common incorrect:** “One gives index, one gives value for arrays only.” **Follow-up:** Which works with Set? **Related:** [Loops](../06-08-operators-control-iteration.md).

**Q052. Why avoid `for...in` for array values?** — **Expected:** It enumerates property keys, can include non-index/inherited enumerable keys, and yields string keys. **Reasoning:** Arrays are objects. **Common incorrect:** “Because it is always slower.” **Follow-up:** Preferred value loop? **Related:** [Loops](../06-08-operators-control-iteration.md).

**Q053. Difference `while` vs `do...while`?** — **Expected:** `while` checks before first iteration; `do...while` runs body once before checking. **Reasoning:** Entry condition location. **Common incorrect:** “No semantic difference.” **Follow-up:** Give one valid do-while use. **Related:** [Loops](../06-08-operators-control-iteration.md).

**Q054. What does `break` do?** — **Expected:** Abruptly exits the targeted loop/switch/labelled construct. **Reasoning:** Completion behavior. **Common incorrect:** “Exits the whole program.” **Follow-up:** How can labels affect break? **Related:** [Loops](../06-08-operators-control-iteration.md).

**Q055. What does `continue` do?** — **Expected:** Skips to the next iteration of the targeted loop according to loop update/test rules. **Reasoning:** It does not exit the loop. **Common incorrect:** “Same as break.” **Follow-up:** Can it target a label? **Related:** [Loops](../06-08-operators-control-iteration.md).

**Q056. What is an iterable?** — **Expected:** A value exposing `Symbol.iterator` that returns an iterator. **Reasoning:** Defines for-of/spread compatibility. **Common incorrect:** “Anything with length.” **Follow-up:** Is a plain object iterable by default? **Related:** [Iterators](../builtins-iteration-binary.md#27--iterators-and-iterables).

**Q057. What is an iterator?** — **Expected:** An object whose `next()` returns iterator-result objects `{value, done}`; often itself iterable. **Reasoning:** Producer protocol. **Common incorrect:** “An array method.” **Follow-up:** What signals completion? **Related:** [Iterators](../builtins-iteration-binary.md#27--iterators-and-iterables).

**Q058. Does spread always mean the same operation?** — **Expected:** No; array/argument spread consumes iterables, object spread copies own enumerable properties. **Reasoning:** Grammar context changes semantics. **Common incorrect:** “It always clones.” **Follow-up:** Why isn't object spread deep? **Related:** [Advanced APIs](../37-47-advanced-language-apis.md#44--spread-and-rest).

**Q059. What is iterator closing?** — **Expected:** Some consumers call an iterator's `return()` when iteration ends abruptly, allowing cleanup. **Reasoning:** Early break can signal producer. **Common incorrect:** “GC immediately deletes the iterator.” **Follow-up:** How do generators use finally here? **Related:** [Iterators](../builtins-iteration-binary.md#27--iterators-and-iterables).

**Q060. What can happen when mutating a collection during iteration?** — **Expected:** Visited/skipped behavior depends on the specific algorithm/iterator; do not assume one universal snapshot rule. **Reasoning:** Each API defines semantics. **Common incorrect:** “Mutation is always forbidden.” **Follow-up:** Safer design? **Related:** [Loops](../06-08-operators-control-iteration.md).

## Function fundamentals

**Q061. Function declaration vs expression?** — **Expected:** Declaration introduces a binding through declaration instantiation; expression creates a function value when evaluated. **Reasoning:** Timing/scope differ. **Common incorrect:** “Only syntax placement differs.” **Follow-up:** Named function expression benefit? **Related:** [Functions](../09-functions.md).

**Q062. Arrow function vs ordinary function?** — **Expected:** Arrow lacks own `this`, `arguments`, `super`, `new.target`, and constructibility; uses lexical `this`. **Reasoning:** Not merely shorter syntax. **Common incorrect:** “Arrow is always better.” **Follow-up:** Why avoid arrow as dynamic object method? **Related:** [Functions](../09-functions.md).

**Q063. What is a first-class function?** — **Expected:** Functions are values that can be stored, passed, returned, and composed. **Reasoning:** Enables callbacks/HOFs. **Common incorrect:** “A function declared at top level.” **Follow-up:** Define higher-order function. **Related:** [Functions](../09-functions.md).

**Q064. What is a higher-order function?** — **Expected:** A function that takes functions and/or returns a function. **Reasoning:** Examples map/filter/factories. **Common incorrect:** “A function with many parameters.” **Follow-up:** Give a closure-returning example. **Related:** [Functions](../09-functions.md).

**Q065. What are default parameters?** — **Expected:** Parameter initializers used when the corresponding argument is `undefined`/missing. **Reasoning:** `null` does not trigger default. **Common incorrect:** “Any falsy argument triggers default.” **Follow-up:** `f(null)` with `x=1`? **Related:** [Functions](../09-functions.md).

**Q066. Rest parameters vs `arguments`?** — **Expected:** Rest is a real Array of remaining arguments with lexical parameter syntax; `arguments` is legacy array-like and has historical mapping semantics. **Reasoning:** Prefer rest for new code. **Common incorrect:** “Both are arrays.” **Follow-up:** Do arrows have `arguments`? **Related:** [Functions](../09-functions.md).

**Q067. What does argument spread do?** — **Expected:** Iterates an iterable and supplies yielded values as separate call arguments. **Reasoning:** It is iterator-based. **Common incorrect:** “Copies object properties into parameters.” **Follow-up:** Can a Set be spread into a call? **Related:** [Functions](../09-functions.md).

**Q068. What is recursion?** — **Expected:** A function invokes itself directly/indirectly until a base condition; deep recursion can exhaust implementation stack resources. **Reasoning:** Calls create nested execution work. **Common incorrect:** “JavaScript always optimizes tail recursion.” **Follow-up:** What alternative handles deep traversals? **Related:** [Functions](../09-functions.md).

**Q069. What is a callback?** — **Expected:** A function passed to be invoked by another function/API; it may be synchronous or asynchronous depending on contract. **Reasoning:** “Callback” does not imply timing. **Common incorrect:** “Callbacks are always async.” **Follow-up:** Is Array.map callback async? **Related:** [Functions](../09-functions.md).

**Q070. Output: `[1,2,3].map(x => { x * 2 })`?** — **Expected:** `[undefined, undefined, undefined]` because block-bodied arrow has no return. **Reasoning:** Expression-body implicit return applies only without braces. **Common incorrect:** `[2,4,6]`. **Follow-up:** Two correct fixes? **Related:** [Functions](../09-functions.md).
