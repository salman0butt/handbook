# Q071–Q140 — Intermediate Functions, Objects & Built-ins

## Closures, scope, this and invocation

**Q071. What is a closure?** — **Expected:** A function plus access to its surrounding lexical environment/bindings after creation. **Reasoning:** It retains binding access, not copied snapshots. **Common incorrect:** “A function that returned.” **Follow-up:** Can non-returned functions be closures? **Related:** [Function internals](../10-function-internals.md).

**Q072. Do closures capture values or bindings?** — **Expected:** Bindings; later mutation of the binding can be observed. **Reasoning:** Two closures can share one `let`. **Common incorrect:** “Value at creation time always.” **Follow-up:** Build shared counter closures. **Related:** [Function internals](../10-function-internals.md).

**Q073. Why do `let` loop closures usually get 0,1,2 while `var` gets final value?** — **Expected:** `for` lexical declarations can create per-iteration bindings; var uses one function/global binding. **Reasoning:** Binding identity differs. **Common incorrect:** “Arrow functions remember index.” **Follow-up:** How did old code fix var loops? **Related:** [Function internals](../10-function-internals.md).

**Q074. Can closures cause leaks?** — **Expected:** They can contribute if long-lived reachable functions retain no-longer-needed object graphs; closures themselves are normal. **Reasoning:** Leak is reachability/lifetime mismatch. **Common incorrect:** “Every closure leaks memory.” **Follow-up:** Name a listener leak example. **Related:** [Memory](../37-47-advanced-language-apis.md#42--memory-mental-model).

**Q075. What determines `this` in an ordinary function?** — **Expected:** Primarily the call site/reference: plain, property call, explicit call, construct. **Reasoning:** Not lexical ownership. **Common incorrect:** “Where function was defined.” **Follow-up:** Arrow exception? **Related:** [`this`](../11-this.md).

**Q076. Output: `const f=obj.m; f()` for method using this?** — **Expected:** In strict/module code, plain-call `this` is undefined, so property access may throw. **Reasoning:** Detached function lost property-reference base. **Common incorrect:** “Still obj.” **Follow-up:** Three fixes? **Related:** [`this`](../11-this.md).

**Q077. How does arrow `this` work?** — **Expected:** Arrow has no own this binding; `this` resolves lexically from surrounding context. **Reasoning:** `call/bind` cannot replace it. **Common incorrect:** “Arrow this is always window.” **Follow-up:** Why useful in callbacks inside methods? **Related:** [`this`](../11-this.md).

**Q078. `call` vs `apply`?** — **Expected:** Both invoke with explicit this; call takes argument list, apply takes array-like argument collection. **Reasoning:** Immediate invocation. **Common incorrect:** “apply permanently binds.” **Follow-up:** What does bind do? **Related:** [Objects/call-new](../12-15-objects-and-descriptors.md#12--call-apply-bind-and-new).

**Q079. What does `bind` return?** — **Expected:** A new bound function with stored this/leading arguments; target is not invoked immediately. **Reasoning:** Function wrapper semantics. **Common incorrect:** “Same function mutated.” **Follow-up:** Can a bound constructor be used with new? **Related:** [Objects/call-new](../12-15-objects-and-descriptors.md#12--call-apply-bind-and-new).

**Q080. What are conceptual steps of `new`?** — **Expected:** Construct a receiver linked to constructor prototype, run constructor semantics with it, return explicit object result if provided otherwise receiver. **Reasoning:** `[[Construct]]` model. **Common incorrect:** “Just calls function with empty object.” **Follow-up:** What does `new.target` reveal? **Related:** [Objects/call-new](../12-15-objects-and-descriptors.md#12--call-apply-bind-and-new).

## Objects and descriptors

**Q081. What types can object property keys be?** — **Expected:** String or Symbol; numeric syntax becomes string keys. **Reasoning:** Use Map for arbitrary object keys. **Common incorrect:** “Any JavaScript value.” **Follow-up:** What happens with `{[{}]:1}`? **Related:** [Objects](../12-15-objects-and-descriptors.md).

**Q082. Own vs inherited property?** — **Expected:** Own descriptor belongs directly to object; inherited is found via prototype chain. **Reasoning:** Lookup and enumeration differ. **Common incorrect:** “Inherited properties are copied.” **Follow-up:** Own-only test? **Related:** [Objects](../12-15-objects-and-descriptors.md).

**Q083. `Object.hasOwn` vs `in`?** — **Expected:** hasOwn checks own property only; in sees own or inherited property. **Reasoning:** Important for dictionaries/security. **Common incorrect:** “Both same.” **Follow-up:** Why prefer hasOwn over calling obj.hasOwnProperty? **Related:** [Objects](../12-15-objects-and-descriptors.md).

**Q084. What is a data descriptor?** — **Expected:** Property descriptor using value/writable plus enumerable/configurable. **Reasoning:** Distinct from accessor descriptor. **Common incorrect:** “Any normal object property definition object.” **Follow-up:** Can descriptor have value and get together? **Related:** [Descriptors](../12-15-objects-and-descriptors.md#14--property-descriptors).

**Q085. What is an accessor descriptor?** — **Expected:** Property descriptor with get/set functions plus enumerable/configurable, no data value/writable fields. **Reasoning:** Reads/writes can execute code. **Common incorrect:** “A private field.” **Follow-up:** What is this in inherited getter? **Related:** [Descriptors](../12-15-objects-and-descriptors.md#14--property-descriptors).

**Q086. What do configurable/enumerable/writable mean?** — **Expected:** Reconfiguration/deletion ability; visibility to enumerable-key operations; ability to change data property value by ordinary assignment. **Reasoning:** Independent attributes. **Common incorrect:** “All are access control.” **Follow-up:** Defaults in defineProperty? **Related:** [Descriptors](../12-15-objects-and-descriptors.md#14--property-descriptors).

**Q087. Why can `Object.defineProperty(o,'x',{value:1})` surprise?** — **Expected:** Unspecified writable/enumerable/configurable default false. **Reasoning:** Differs from ordinary literal/assignment defaults. **Common incorrect:** “It creates normal fully writable property.” **Follow-up:** How inspect? **Related:** [Descriptors](../12-15-objects-and-descriptors.md#14--property-descriptors).

**Q088. `Object.keys` vs `Reflect.ownKeys`?** — **Expected:** keys returns own enumerable string keys; Reflect.ownKeys returns all own strings and symbols including non-enumerables. **Reasoning:** Reflection surface differs. **Common incorrect:** “Reflect just includes inherited keys.” **Follow-up:** Which gets symbols only? **Related:** [Descriptors](../12-15-objects-and-descriptors.md#14--property-descriptors).

**Q089. Why is object spread shallow?** — **Expected:** It copies own enumerable property values into a new object; nested object values still designate same objects. **Reasoning:** No recursive clone. **Common incorrect:** “Spread clones nested objects.” **Follow-up:** What else doesn't it preserve? **Related:** [Objects](../12-15-objects-and-descriptors.md).

**Q090. `freeze` vs deep immutability?** — **Expected:** Object.freeze is shallow: own data properties become non-writable and properties non-configurable/extensions prevented, nested referenced objects can still mutate. **Reasoning:** Integrity applies to one object. **Common incorrect:** “Entire graph frozen.” **Follow-up:** When would deep freeze be risky? **Related:** [Integrity](../12-15-objects-and-descriptors.md#15--object-integrity).

## Prototypes and classes

**Q091. What is `[[Prototype]]`?** — **Expected:** Internal link used by ordinary property lookup/delegation, another object or null. **Reasoning:** Not same as public `.prototype` property. **Common incorrect:** “A normal enumerable property.” **Follow-up:** Inspect API? **Related:** [Prototypes](../16-prototypes.md).

**Q092. What is `Ctor.prototype`?** — **Expected:** Public property on a constructible function commonly used as new instances' internal prototype. **Reasoning:** The function itself has a separate internal prototype. **Common incorrect:** “Ctor's own prototype link.” **Follow-up:** What is Object.getPrototypeOf(Ctor)? **Related:** [Prototypes](../16-prototypes.md).

**Q093. Draw `new User()` prototype chain.** — **Expected:** instance → User.prototype → Object.prototype → null (for ordinary setup). **Reasoning:** Delegation chain. **Common incorrect:** “instance → User → Object.” **Follow-up:** Where is method shared? **Related:** [Prototypes](../16-prototypes.md).

**Q094. What is prototype shadowing?** — **Expected:** Own property with same key hides inherited property during lookup. **Reasoning:** Prototype value remains unchanged. **Common incorrect:** “Prototype property deleted.” **Follow-up:** What if inherited property is setter? **Related:** [Prototypes](../16-prototypes.md).

**Q095. Why avoid frequent `Object.setPrototypeOf`?** — **Expected:** It complicates reasoning and can invalidate engine structural/optimization assumptions; create desired chain up front. **Reasoning:** Performance is engine-specific but stable shapes help. **Common incorrect:** “Illegal after construction.” **Follow-up:** Safe creation API? **Related:** [Prototypes](../16-prototypes.md).

**Q096. What is prototype pollution?** — **Expected:** Attacker-controlled data modifies prototype/shared inheritance or injects inherited properties that trusted code later observes. **Reasoning:** Merge/path setters are common vectors. **Common incorrect:** “Any object mutation.” **Follow-up:** Mitigations? **Related:** [Prototypes](../16-prototypes.md).

**Q097. Are classes separate from prototypes?** — **Expected:** No; class methods live on class prototype and inheritance establishes prototype relationships, with added class-specific semantics. **Reasoning:** Classes build on prototype object model. **Common incorrect:** “Classes replaced prototypes in ES6.” **Follow-up:** Where does method live? **Related:** [Classes](../17-classes.md).

**Q098. Where are instance public fields stored?** — **Expected:** As own properties/fields initialized per instance according to class field semantics. **Reasoning:** Unlike prototype methods. **Common incorrect:** “On Class.prototype.” **Follow-up:** Allocation implication of arrow field? **Related:** [Classes](../17-classes.md).

**Q099. What makes `#private` different from `_private`?** — **Expected:** Private names are language-enforced and not ordinary string keys/normal reflection; underscore is convention only. **Reasoning:** Syntax/brand semantics. **Common incorrect:** “Both just naming.” **Follow-up:** Is #private encryption? **Related:** [Classes](../17-classes.md).

**Q100. Why must derived constructor call `super()` before `this`?** — **Expected:** Derived construction initializes the receiver through super/base construction; `this` is unavailable beforehand. **Reasoning:** Derived constructor semantics. **Common incorrect:** “Only because linter says so.” **Follow-up:** Can derived constructor return another object? **Related:** [Classes](../17-classes.md).

## Arrays and collections

**Q101. What is a sparse array hole?** — **Expected:** Missing indexed own property within array length, distinct from present property value undefined. **Reasoning:** Algorithms treat holes differently. **Common incorrect:** “Just undefined.” **Follow-up:** Compare `0 in [,]` vs `[undefined]`. **Related:** [Arrays](../18-arrays.md).

**Q102. `new Array(3)` vs `Array.of(3)`?** — **Expected:** First creates length 3 sparse array; second creates `[3]`. **Reasoning:** Constructor single-number special case. **Common incorrect:** “Both `[3]`.” **Follow-up:** Preferred explicit list creation? **Related:** [Arrays](../18-arrays.md).

**Q103. Mutating alternatives to `toSorted`, `toReversed`, `toSpliced`, `with`?** — **Expected:** `sort`, `reverse`, `splice`, and direct indexed replacement respectively. **Reasoning:** Change-array-by-copy APIs preserve source. **Common incorrect:** “All mutate.” **Follow-up:** Are returned arrays deep copies? **Related:** [Arrays](../18-arrays.md).

**Q104. Why numeric sort needs comparator?** — **Expected:** Default sort compares string representations/code-unit order. **Reasoning:** `[10,2]` can order lexically. **Common incorrect:** “Default ascending numeric.” **Follow-up:** Correct comparator? **Related:** [Arrays](../18-arrays.md).

**Q105. `map` vs `forEach`?** — **Expected:** map creates a result array from callback results; forEach is side-effect iteration returning undefined. **Reasoning:** Different contracts. **Common incorrect:** “Only speed.” **Follow-up:** Which works naturally in transform pipeline? **Related:** [Arrays](../18-arrays.md).

**Q106. `slice` vs `splice`?** — **Expected:** slice returns shallow selected copy without mutating; splice mutates by removing/inserting and returns removed items. **Reasoning:** Similar names, different ownership. **Common incorrect:** “Both mutate.” **Follow-up:** Non-mutating splice alternative? **Related:** [Arrays](../18-arrays.md).

**Q107. `find` vs `filter`?** — **Expected:** find returns first matching value/undefined; filter returns array of all matching elements. **Reasoning:** Cardinality and allocation differ. **Common incorrect:** “find returns index.” **Follow-up:** Method that returns index? **Related:** [Arrays](../18-arrays.md).

**Q108. Map vs Object?** — **Expected:** Map is dynamic arbitrary-key collection with explicit size/iteration and SameValueZero key semantics; Object is record/property/prototype model with string/symbol keys. **Reasoning:** Choose abstraction, not benchmark myth. **Common incorrect:** “Map is always faster.” **Follow-up:** When is object clearer? **Related:** [Collections](../builtins-iteration-binary.md#26--map-set-weakmap-weakset).

**Q109. Set equality semantics?** — **Expected:** SameValueZero: NaN equals NaN, signed zeros are same. **Reasoning:** Distinct from strict/SameValue. **Common incorrect:** “Uses === exactly.” **Follow-up:** Set of two NaNs size? **Related:** [Collections](../builtins-iteration-binary.md#26--map-set-weakmap-weakset).

**Q110. Why can't WeakMap be enumerated?** — **Expected:** Entries depend on GC reachability, which is nondeterministic; enumeration would expose/affect GC-sensitive state. **Reasoning:** Weak key design. **Common incorrect:** “Because it has no iterator implementation accidentally.” **Follow-up:** Use case? **Related:** [Collections](../builtins-iteration-binary.md#26--map-set-weakmap-weakset).

## Strings, Unicode, numbers and BigInt

**Q111. Why can string `.length` exceed visible characters?** — **Expected:** It counts UTF-16 code units; code points may use surrogate pairs and grapheme clusters can span multiple code points. **Reasoning:** Encoding vs user-perceived text. **Common incorrect:** “Length is bytes.” **Follow-up:** How count grapheme clusters? **Related:** [Strings](../builtins-iteration-binary.md#19--strings-and-unicode).

**Q112. Code unit vs code point?** — **Expected:** UTF-16 code unit is 16-bit unit; Unicode code point is abstract scalar/code point that may require two code units. **Reasoning:** String indexing works in code units. **Common incorrect:** “Same thing.” **Follow-up:** How does for-of iterate strings? **Related:** [Strings](../builtins-iteration-binary.md#19--strings-and-unicode).

**Q113. What is Unicode normalization?** — **Expected:** Converts canonically/compatibly equivalent sequences into chosen normalization form; can make composed/decomposed text compare consistently when domain requires. **Reasoning:** Same appearance can have different code points. **Common incorrect:** “Lowercasing.” **Follow-up:** Why not normalize blindly? **Related:** [Strings](../builtins-iteration-binary.md#19--strings-and-unicode).

**Q114. Tagged template use?** — **Expected:** A function receives literal segments and substitutions to implement formatting/escaping/DSL semantics. **Reasoning:** Tag controls interpretation. **Common incorrect:** “Template with HTML automatically safe.” **Follow-up:** Can a tag help parameterize SQL-like DSL safely? **Related:** [Strings](../builtins-iteration-binary.md#19--strings-and-unicode).

**Q115. Why `0.1 + 0.2 !== 0.3`?** — **Expected:** Binary64 cannot exactly represent many decimal fractions; rounded representations/sum differ. **Reasoning:** IEEE-754 approximation. **Common incorrect:** “JavaScript rounds wrong intentionally.” **Follow-up:** Strategy for money? **Related:** [Numbers](../builtins-iteration-binary.md#20--numbers-and-math).

**Q116. What are safe integers?** — **Expected:** Integer values within Number's range where every integer is exactly distinguishable, bounded by MAX/MIN_SAFE_INTEGER. **Reasoning:** Beyond, adjacent integers can map to same Number. **Common incorrect:** “All integers under Infinity.” **Follow-up:** Alternative for huge integers? **Related:** [Numbers](../builtins-iteration-binary.md#20--numbers-and-math).

**Q117. What is `-0`?** — **Expected:** IEEE-754 signed zero Number value; `===` treats it equal to +0, Object.is distinguishes. **Reasoning:** Sign can affect operations like reciprocal. **Common incorrect:** “Parser converts it to 0 and sign disappears always.” **Follow-up:** `1 / -0`? **Related:** [Numbers](../builtins-iteration-binary.md#20--numbers-and-math).

**Q118. BigInt purpose?** — **Expected:** Arbitrary-precision integer arithmetic beyond Number safe-integer limits/for exact integer domains. **Reasoning:** Not decimal floating point. **Common incorrect:** “Makes decimals exact.” **Follow-up:** Can you do `1n + 1`? **Related:** [BigInt](../builtins-iteration-binary.md#21--bigint).

**Q119. Why can't Number and BigInt be mixed in arithmetic directly?** — **Expected:** Language avoids implicit precision-losing numeric conversion for arithmetic; explicit conversion required. **Reasoning:** Different numeric types. **Common incorrect:** “Engine limitation only.” **Follow-up:** Can relational comparison mix them? **Related:** [BigInt](../builtins-iteration-binary.md#21--bigint).

**Q120. BigInt and JSON?** — **Expected:** Standard JSON value model has no BigInt representation; stringify of BigInt requires deliberate transformation/strategy. **Reasoning:** Schema must define encoding such as string. **Common incorrect:** “JSON stores it as huge number safely.” **Follow-up:** How revive? **Related:** [BigInt](../builtins-iteration-binary.md#21--bigint).

## Date, Temporal, RegExp, Symbols

**Q121. What does Date fundamentally represent?** — **Expected:** A timestamp value (milliseconds from epoch within valid range) with methods viewing in local/UTC forms. **Reasoning:** It doesn't intrinsically store arbitrary named time zone. **Common incorrect:** “A date string plus timezone.” **Follow-up:** What does toISOString use? **Related:** [Date](../builtins-iteration-binary.md#22--date-and-time).

**Q122. Why are ambiguous date strings risky?** — **Expected:** Locale-looking forms can be parsed inconsistently/ambiguous; cross-system contracts should use explicit ISO/schema. **Reasoning:** Parsing and timezone assumptions cause bugs. **Common incorrect:** “Browser always uses user's locale reliably.” **Follow-up:** Safer representation for instant? **Related:** [Date](../builtins-iteration-binary.md#22--date-and-time).

**Q123. Why can adding 24 hours differ from “same local time tomorrow”?** — **Expected:** DST/time-zone offset transitions change civil-day elapsed duration. **Reasoning:** Instant arithmetic vs calendar/zoned arithmetic. **Common incorrect:** “A day is always 24h in every context.” **Follow-up:** Which API models this explicitly? **Related:** [Temporal](../builtins-iteration-binary.md#23--temporal).

**Q124. Why does Temporal exist?** — **Expected:** To provide explicit immutable-style types for instants, zones, dates/times, calendars, durations and safer arithmetic/parsing than Date. **Reasoning:** Separate concepts instead of overloaded Date. **Common incorrect:** “Only faster Date.” **Follow-up:** PlainDate vs ZonedDateTime? **Related:** [Temporal](../builtins-iteration-binary.md#23--temporal).

**Q125. Does Stage 4 Temporal mean every browser has it?** — **Expected:** No; finished/standardized status and implementation availability differ. **Reasoning:** Check target engines/runtime. **Common incorrect:** “Stage 4 guarantees universal shipping.” **Follow-up:** What should production do on unsupported targets? **Related:** [Version baseline](../version-baseline.md).

**Q126. Regex `g` vs `y`?** — **Expected:** global searches for successive matches; sticky requires match at current lastIndex position. **Reasoning:** Both interact with lastIndex but matching strategy differs. **Common incorrect:** “Aliases.” **Follow-up:** Parser/tokenizer use for sticky? **Related:** [RegExp](../builtins-iteration-binary.md#24--regular-expressions).

**Q127. What are named capture groups?** — **Expected:** Captures associated with names accessible through match groups and usable in replacements/backrefs syntax. **Reasoning:** Improves maintainability over numeric-only groups. **Common incorrect:** “Named regex variables globally.” **Follow-up:** How access `match.groups`? **Related:** [RegExp](../builtins-iteration-binary.md#24--regular-expressions).

**Q128. What is ReDoS?** — **Expected:** Regex denial-of-service where pathological backtracking on crafted input consumes excessive CPU. **Reasoning:** Pattern/input complexity is security surface. **Common incorrect:** “Regex injection only.” **Follow-up:** Mitigations? **Related:** [RegExp](../builtins-iteration-binary.md#24--regular-expressions).

**Q129. What makes Symbols unique?** — **Expected:** `Symbol()` creates unique primitive identities even with same description. **Reasoning:** Description is debugging label, not identity. **Common incorrect:** “Same description means same Symbol.” **Follow-up:** How get shared symbol? **Related:** [Symbols](../builtins-iteration-binary.md#25--symbols).

**Q130. `Symbol.for` purpose?** — **Expected:** Retrieves/creates symbol in global symbol registry by string key. **Reasoning:** Enables cross-module/realm-agent registry identity according to standard semantics. **Common incorrect:** “Same as Symbol().” **Follow-up:** `Symbol.keyFor`? **Related:** [Symbols](../builtins-iteration-binary.md#25--symbols).

**Q131. Are Symbol properties private?** — **Expected:** No; less collision-prone/non-string but discoverable via reflection such as Reflect.ownKeys/getOwnPropertySymbols. **Reasoning:** Privacy requires private fields/closures. **Common incorrect:** “Symbols are hidden.” **Follow-up:** Why use Symbol.iterator? **Related:** [Symbols](../builtins-iteration-binary.md#25--symbols).

**Q132. What is a well-known Symbol?** — **Expected:** Standard Symbol value used as a protocol hook, e.g. iterator/toPrimitive/hasInstance. **Reasoning:** Lets objects customize language operations. **Common incorrect:** “A symbol stored globally by app.” **Follow-up:** Which customizes instanceof? **Related:** [Symbols](../builtins-iteration-binary.md#25--symbols).

## Iterator/generator and binary basics

**Q133. Generator function syntax?** — **Expected:** `function* name(){ yield ... }`, producing generator objects when called. **Reasoning:** Calling doesn't run body to completion immediately. **Common incorrect:** “`async function`.” **Follow-up:** What does next return? **Related:** [Generators](../builtins-iteration-binary.md#28--generators).

**Q134. `yield` vs `return` in generator?** — **Expected:** yield suspends with done false and can resume; return completes generator with done true. **Reasoning:** Generator state machine. **Common incorrect:** “Both permanently finish.” **Follow-up:** What does yield* do? **Related:** [Generators](../builtins-iteration-binary.md#28--generators).

**Q135. What does `yield*` do?** — **Expected:** Delegates iteration/control to another iterable/iterator according to generator delegation semantics. **Reasoning:** Composes generators. **Common incorrect:** “Spreads array into yield expression once.” **Follow-up:** Use with nested sequences? **Related:** [Generators](../builtins-iteration-binary.md#28--generators).

**Q136. What is ArrayBuffer?** — **Expected:** Raw fixed-length/resizable-capable binary buffer abstraction depending current APIs; views interpret bytes. **Reasoning:** Buffer itself doesn't expose normal element type semantics. **Common incorrect:** “An Array of numbers.” **Follow-up:** Name two views. **Related:** [Binary data](../builtins-iteration-binary.md#29--typed-arrays-and-binary-data).

**Q137. TypedArray vs DataView?** — **Expected:** Typed arrays expose homogeneous typed indexed elements; DataView reads/writes multiple numeric types at byte offsets with endianness control. **Reasoning:** Different binary protocol needs. **Common incorrect:** “DataView is faster typed array.” **Follow-up:** When endianness matters? **Related:** [Binary data](../builtins-iteration-binary.md#29--typed-arrays-and-binary-data).

**Q138. Can two typed-array views share memory?** — **Expected:** Yes if backed by same ArrayBuffer/SharedArrayBuffer; writes can be observed through other views. **Reasoning:** Views interpret same bytes. **Common incorrect:** “Constructing view clones buffer.” **Follow-up:** What changes with transfer? **Related:** [Binary data](../builtins-iteration-binary.md#29--typed-arrays-and-binary-data).

**Q139. Why use Atomics?** — **Expected:** To perform defined synchronized operations on shared memory and coordinate agents/workers. **Reasoning:** Ordinary shared read-modify-write can race. **Common incorrect:** “Makes all JS multi-threaded automatically.” **Follow-up:** When prefer message passing? **Related:** [Atomics](../builtins-iteration-binary.md#30--atomics-and-shared-memory).

**Q140. What is `Error.cause` for?** — **Expected:** Wrap/translate an error while retaining underlying failure for diagnostics. **Reasoning:** Preserve causality across layers. **Common incorrect:** “Replaces stack trace with string.” **Follow-up:** How would custom domain error expose stable code too? **Related:** [Errors](../builtins-iteration-binary.md#31--errors).
