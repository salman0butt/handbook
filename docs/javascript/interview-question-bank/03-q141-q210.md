# Q141–Q210 — Advanced Async, Modules & Browser JavaScript

## Promises

**Q141. What are Promise states?** — **Expected:** Pending, fulfilled, rejected; fulfilled/rejected are settled. **Reasoning:** State is one-way after settlement. **Common incorrect:** “pending, resolved, failed.” **Follow-up:** Resolved vs fulfilled? **Related:** [Promises](../32-promises.md).

**Q142. Resolved vs fulfilled Promise?** — **Expected:** Resolved means resolution is locked to a value/thenable outcome; it may still be pending while adopting another promise. Fulfilled is final successful state. **Reasoning:** Resolution procedure can adopt. **Common incorrect:** “Synonyms.” **Follow-up:** Resolve with pending Promise example. **Related:** [Promises](../32-promises.md).

**Q143. Does Promise executor run synchronously?** — **Expected:** Yes, constructor calls executor immediately; reactions run asynchronously as jobs. **Reasoning:** Separate setup from continuation. **Common incorrect:** “Everything inside Promise constructor is async.” **Follow-up:** Output prediction with console logs? **Related:** [Promises](../32-promises.md).

**Q144. What does `.then()` return?** — **Expected:** A new Promise whose outcome depends on handler result/throw/thenable. **Reasoning:** Enables chains. **Common incorrect:** “Same Promise.” **Follow-up:** What if handler returns 5? **Related:** [Promises](../32-promises.md).

**Q145. What if a `then` handler throws?** — **Expected:** The Promise returned by `then` rejects with the thrown reason. **Reasoning:** Handler completion maps to chain outcome. **Common incorrect:** “Throw escapes synchronously to original caller.” **Follow-up:** How catch it? **Related:** [Promises](../32-promises.md).

**Q146. What is thenable assimilation?** — **Expected:** Promise resolution recognizes objects/functions with callable `then` and adopts their eventual outcome via specified procedure. **Reasoning:** Interoperability. **Common incorrect:** “Only native Promises can be awaited.” **Follow-up:** Security implication of untrusted thenable? **Related:** [Promises](../32-promises.md).

**Q147. `Promise.all` behavior on rejection?** — **Expected:** Aggregate Promise rejects when an input rejection determines failure; underlying operations are not automatically cancelled. **Reasoning:** Composition ≠ cancellation. **Common incorrect:** “Stops every request immediately.” **Follow-up:** How cancel fetches? **Related:** [Promises](../32-promises.md).

**Q148. When use `allSettled`?** — **Expected:** When all outcomes matter and partial failure is expected/independent. **Reasoning:** It returns per-input statuses without short-circuit rejection. **Common incorrect:** “Always better all.” **Follow-up:** Reporting dashboard example? **Related:** [Promises](../32-promises.md).

**Q149. `Promise.any`?** — **Expected:** Fulfills with first fulfillment; rejects with AggregateError if all reject. **Reasoning:** Success race. **Common incorrect:** “Same as race.” **Follow-up:** How race differs on first rejection? **Related:** [Promises](../32-promises.md).

**Q150. `Promise.race` cancellation?** — **Expected:** None automatically; it settles aggregate with first settled input while losers keep running. **Reasoning:** Need separate abort protocol. **Common incorrect:** “Cancels losers.” **Follow-up:** Why Promise-based timeout may leak work? **Related:** [Promises](../32-promises.md).

**Q151. `Promise.withResolvers` use?** — **Expected:** Creates capability object `{promise,resolve,reject}` when settlement controls must be separated from setup. **Reasoning:** Avoid awkward externally scoped constructor callbacks. **Common incorrect:** “Makes Promise synchronous.” **Follow-up:** When constructor is clearer? **Related:** [Promises](../32-promises.md).

**Q152. `Promise.try` purpose?** — **Expected:** In the 2026 baseline, turns callback execution—including sync throws/thenable returns—into a Promise outcome. **Reasoning:** Normalize sync/async callback contract. **Common incorrect:** “Retries Promise.” **Follow-up:** Compatibility concern? **Related:** [Promises](../32-promises.md).

## Async/await and event loop

**Q153. What does async function return?** — **Expected:** A Promise, fulfilled from returned value/adopted thenable or rejected from throw. **Reasoning:** Async API contract is Promise-based. **Common incorrect:** “Returns raw value after await.” **Follow-up:** `async()=>5` result? **Related:** [Async/await](../33-async-await.md).

**Q154. Does `await` block the thread?** — **Expected:** No; it suspends async function continuation while host/event loop can run other work. **Reasoning:** Continuation resumes via Promise job semantics. **Common incorrect:** “Thread sleeps.” **Follow-up:** Can CPU loop before await still block? **Related:** [Async/await](../33-async-await.md).

**Q155. Why `await array.forEach(async fn)` doesn't wait?** — **Expected:** forEach ignores callback return values and itself returns undefined; callback Promises aren't composed. **Reasoning:** API contract. **Common incorrect:** “await is buggy in loops.” **Follow-up:** Parallel and sequential fixes? **Related:** [Async/await](../33-async-await.md).

**Q156. Sequential vs parallel awaits?** — **Expected:** Starting and awaiting one before starting another serializes; start independent Promises first then compose, with concurrency bounds as needed. **Reasoning:** Operation start timing. **Common incorrect:** “Two await lines always parallel.” **Follow-up:** Why not Promise.all 100k requests? **Related:** [Async/await](../33-async-await.md).

**Q157. What is top-level await?** — **Expected:** Await directly in ESM module evaluation; makes module async and can delay dependents. **Reasoning:** Graph-level effect. **Common incorrect:** “Allowed in any script now.” **Follow-up:** Cycle/startup risk? **Related:** [Modules](../36-modules.md).

**Q158. ECMAScript Job vs browser task?** — **Expected:** Job is language spec queued work such as Promise reactions; browser tasks are host/HTML event-loop units such as timers/events/script tasks. **Reasoning:** Language/host boundary. **Common incorrect:** “Same queue name.” **Follow-up:** Who integrates jobs? **Related:** [Event loop](../34-event-loop.md).

**Q159. Output A/timer B/Promise C/D?** — **Expected:** A D C B in typical browser: sync first, Promise microtask/job checkpoint, later timer task. **Reasoning:** Current task then microtasks then later task. **Common incorrect:** A B C D. **Follow-up:** Does 0 ms mean immediate? **Related:** [Event loop](../34-event-loop.md).

**Q160. Can microtasks starve rendering?** — **Expected:** Yes, recursively queued microtasks can keep checkpoint draining and delay tasks/rendering. **Reasoning:** Async doesn't imply fairness. **Common incorrect:** “Browser renders after every Promise.” **Follow-up:** Mitigation? **Related:** [Event loop](../34-event-loop.md).

**Q161. Is `setTimeout` ECMAScript?** — **Expected:** No; timer API supplied by browser/Node/host. **Reasoning:** ECMA-262 does not define it. **Common incorrect:** “Core async JavaScript.” **Follow-up:** What core async abstraction exists? **Related:** [Event loop](../34-event-loop.md).

**Q162. What does zero-delay timer guarantee?** — **Expected:** At most eligibility after host minimum/scheduling rules; not immediate execution or exact latency. **Reasoning:** Queue/load/clamping. **Common incorrect:** “Exactly 0 ms later.” **Follow-up:** Background tab behavior? **Related:** [Browser](../paradigms-patterns-browser.md#59--browser-timers-and-scheduling).

**Q163. Why can JS have races if main-thread tasks run to completion?** — **Expected:** Async operations complete in nondeterministic order across jobs/tasks; workers/tabs/server also introduce concurrency. **Reasoning:** Race spans turns, not simultaneous instructions only. **Common incorrect:** “Single-thread means no races.” **Follow-up:** Stale search example? **Related:** [Concurrency](../architecture-and-production.md#85--concurrency-and-race-conditions).

## Async iteration and modules

**Q164. Async iterable protocol?** — **Expected:** `Symbol.asyncIterator` returns iterator whose `next()` resolves to iterator result. **Reasoning:** Promise-based sequence. **Common incorrect:** “Array of Promises.” **Follow-up:** Consumer syntax? **Related:** [Async iteration](../35-async-iteration.md).

**Q165. What does `for await...of` do?** — **Expected:** Sequentially obtains/awaits iterator results and yields values; can adapt sync iterables too. **Reasoning:** Streaming flow. **Common incorrect:** “Runs all items parallel.” **Follow-up:** Backpressure benefit? **Related:** [Async iteration](../35-async-iteration.md).

**Q166. Does breaking async iteration cancel network automatically?** — **Expected:** Iterator closing occurs, but underlying I/O needs its own cancellation integration. **Reasoning:** Protocol boundaries. **Common incorrect:** “Break aborts fetch.” **Follow-up:** How wire AbortSignal? **Related:** [Async iteration](../35-async-iteration.md).

**Q167. What is ESM static graph?** — **Expected:** Static import declarations expose dependencies before evaluation, enabling linking/loading/analyzability. **Reasoning:** Imports are syntax with module semantics. **Common incorrect:** “Graph built only as functions execute.” **Follow-up:** Dynamic import difference? **Related:** [Modules](../36-modules.md).

**Q168. What is a live import binding?** — **Expected:** Import observes exporting module's binding updates rather than copying value; importer cannot reassign import binding. **Reasoning:** Module environment linkage. **Common incorrect:** “Destructuring copy.” **Follow-up:** Counter example? **Related:** [Modules](../36-modules.md).

**Q169. Why can module cycles fail?** — **Expected:** Graph linking creates bindings before all evaluations; cycle may read an exported lexical binding while uninitialized. **Reasoning:** Live binding + evaluation order/TDZ. **Common incorrect:** “Modules execute twice.” **Follow-up:** Architecture fixes? **Related:** [Modules](../36-modules.md).

**Q170. `import()` returns what?** — **Expected:** Promise resolving to module namespace object after loading/linking/evaluation. **Reasoning:** Dynamic asynchronous module acquisition. **Common incorrect:** “Default export value.” **Follow-up:** Lazy route use? **Related:** [Modules](../36-modules.md).

**Q171. Is module namespace object ordinary mutable object?** — **Expected:** No, exotic object exposing module exports with special semantics. **Reasoning:** Live bindings/read-only import view. **Common incorrect:** “Just `{...exports}`.” **Follow-up:** Can assign namespace.x? **Related:** [Modules](../36-modules.md).

**Q172. Import attributes language vs host role?** — **Expected:** ECMAScript standardizes syntax/metadata records; host decides supported module types/attribute meaning/loading. **Reasoning:** Module system crosses host boundary. **Common incorrect:** “ECMA-262 defines JSON network loading fully.” **Follow-up:** Browser MIME role? **Related:** [Modules](../36-modules.md).

## Resource management, proxy, reflect

**Q173. Why explicit resource management if GC exists?** — **Expected:** GC lifetime is nondeterministic and memory-focused; locks/files/subscriptions need deterministic cleanup on scope exit. **Reasoning:** Correctness lifetime ≠ reachability cleanup. **Common incorrect:** “using forces GC.” **Follow-up:** Sync vs async disposal symbols? **Related:** [Advanced APIs](../37-47-advanced-language-apis.md#37--explicit-resource-management).

**Q174. What does `using` conceptually guarantee?** — **Expected:** Registered disposable resource is disposed when scope exits, including abrupt completion, with standardized error handling. **Reasoning:** Structured lifetime. **Common incorrect:** “Only calls close on normal return.” **Follow-up:** What is SuppressedError for? **Related:** [Advanced APIs](../37-47-advanced-language-apis.md#37--explicit-resource-management).

**Q175. What is Proxy target/handler?** — **Expected:** Target is wrapped object/function; handler provides traps intercepting internal operations. **Reasoning:** Interposition. **Common incorrect:** “Proxy copies target.” **Follow-up:** Name get/set traps. **Related:** [Advanced APIs](../37-47-advanced-language-apis.md#38--proxy).

**Q176. What are Proxy invariants?** — **Expected:** Constraints traps must obey so they cannot report states inconsistent with target's non-configurable/extensibility rules. **Reasoning:** Preserves language object integrity. **Common incorrect:** “Trap can return anything.” **Follow-up:** What happens on violation? **Related:** [Advanced APIs](../37-47-advanced-language-apis.md#38--proxy).

**Q177. Why use Reflect inside Proxy traps?** — **Expected:** Delegates default operation with correct receiver/arguments and matching internal-operation semantics instead of reimplementing edge cases. **Reasoning:** Transparent forwarding. **Common incorrect:** “Reflect disables proxy.” **Follow-up:** Reflect.get receiver importance? **Related:** [Advanced APIs](../37-47-advanced-language-apis.md#39--reflect).

**Q178. What does Proxy.revocable provide?** — **Expected:** Proxy plus revoke function after which operations on proxy throw. **Reasoning:** Capability lifetime/control. **Common incorrect:** “Deletes target.” **Follow-up:** Plugin use case? **Related:** [Advanced APIs](../37-47-advanced-language-apis.md#38--proxy).

**Q179. Proxy private-field issue?** — **Expected:** Private fields rely on brand checks/internal receiver; a proxy is a distinct receiver and naïve forwarding can fail for methods/accessors expecting branded target. **Reasoning:** Proxy not transparent to all internal slots/private names. **Common incorrect:** “Proxy intercepts #private directly.” **Follow-up:** Binding method workaround trade-off? **Related:** [Advanced APIs](../37-47-advanced-language-apis.md#38--proxy).

**Q180. What is metaprogramming risk?** — **Expected:** Dynamic semantics obscure contracts/tooling/optimization and can turn untrusted names/code into injection or authority issues. **Reasoning:** Use explicit APIs first. **Common incorrect:** “Metaprogramming means reflection is insecure by definition.” **Follow-up:** Safe Symbol metadata pattern? **Related:** [Advanced APIs](../37-47-advanced-language-apis.md#40--metaprogramming).

## Browser DOM/events/forms

**Q181. Is DOM part of JavaScript?** — **Expected:** No; DOM is Web API exposed by browser host to JS. **Reasoning:** ECMAScript can run without document. **Common incorrect:** “Yes because document is global.” **Follow-up:** Node equivalent? **Related:** [Browser](../paradigms-patterns-browser.md#51--dom-mental-model).

**Q182. DOM vs rendered page?** — **Expected:** DOM is document node model; rendering uses style/layout/paint/compositing structures and may not map one-to-one. **Reasoning:** Mutation can trigger rendering work. **Common incorrect:** “DOM is pixels.” **Follow-up:** What is layout thrash? **Related:** [Browser](../paradigms-patterns-browser.md#51--dom-mental-model).

**Q183. querySelector vs querySelectorAll?** — **Expected:** First matching Element/null vs static NodeList of matches. **Reasoning:** CSS selector APIs, cardinality/collection semantics. **Common incorrect:** “Both live HTMLCollections.” **Follow-up:** Which classic API can be live? **Related:** [Browser](../paradigms-patterns-browser.md#52--dom-selection-and-traversal).

**Q184. children vs childNodes?** — **Expected:** children contains element children (HTMLCollection); childNodes includes nodes such as text/comments (NodeList). **Reasoning:** DOM node types. **Common incorrect:** “Same contents.” **Follow-up:** Why whitespace text nodes matter? **Related:** [Browser](../paradigms-patterns-browser.md#52--dom-selection-and-traversal).

**Q185. Why prefer textContent for untrusted text?** — **Expected:** It inserts text rather than parsing HTML, avoiding HTML interpretation/XSS sink behavior. **Reasoning:** Data vs code/markup boundary. **Common incorrect:** “innerHTML escapes automatically.” **Follow-up:** When rich HTML required? **Related:** [Browser](../paradigms-patterns-browser.md#53--dom-manipulation).

**Q186. Event target vs currentTarget?** — **Expected:** target is dispatch origin/retargeted target; currentTarget is EventTarget whose listener is currently executing. **Reasoning:** Delegation/bubbling. **Common incorrect:** “Always same.” **Follow-up:** Which use for delegated closest? **Related:** [Browser](../paradigms-patterns-browser.md#54--browser-events).

**Q187. Capture/target/bubble?** — **Expected:** Event traverses ancestor capture phase, target phase, then bubbling ancestors if event bubbles. **Reasoning:** Listener phase options. **Common incorrect:** “Browser only bubbles.” **Follow-up:** How register capture listener? **Related:** [Browser](../paradigms-patterns-browser.md#54--browser-events).

**Q188. preventDefault vs stopPropagation?** — **Expected:** preventDefault asks to cancel default action; stopPropagation stops further propagation. **Reasoning:** Behavior vs routing are separate. **Common incorrect:** “Both stop event.” **Follow-up:** stopImmediatePropagation? **Related:** [Browser](../paradigms-patterns-browser.md#54--browser-events).

**Q189. What is event delegation?** — **Expected:** Attach listener to ancestor and inspect bubbled event target/closest descendant to handle many/dynamic children. **Reasoning:** Lifecycle/listener efficiency. **Common incorrect:** “Clone same handler to children.” **Follow-up:** Boundary check needed? **Related:** [Browser](../paradigms-patterns-browser.md#54--browser-events).

**Q190. Why use listener `signal` option?** — **Expected:** AbortSignal can remove listener automatically with lifecycle cancellation. **Reasoning:** Prevent cleanup leaks. **Common incorrect:** “Stops event propagation.” **Follow-up:** Feature-level AbortController pattern? **Related:** [Browser](../paradigms-patterns-browser.md#54--browser-events).

**Q191. Why server validation if HTML validation exists?** — **Expected:** Client is attacker-controlled/untrusted; constraint validation is UX only, server must enforce security/business rules. **Reasoning:** Trust boundary. **Common incorrect:** “Required attribute is enough.” **Follow-up:** What should client validation optimize? **Related:** [Browser](../paradigms-patterns-browser.md#55--forms-and-validation).

**Q192. FormData use?** — **Expected:** Web API to construct key/value form payload from form controls or manually append values. **Reasoning:** Browser form serialization. **Common incorrect:** “ECMAScript Map subclass.” **Follow-up:** How are files represented? **Related:** [Browser](../paradigms-patterns-browser.md#55--forms-and-validation).

## Fetch, URL, storage, timers, workers, clone

**Q193. Is fetch core JS?** — **Expected:** No; Web API (also adopted by some runtimes as host API). **Reasoning:** ECMA-262 doesn't define HTTP. **Common incorrect:** “Promise means fetch is ECMAScript.” **Follow-up:** What part is ECMAScript? **Related:** [Browser](../paradigms-patterns-browser.md#56--browser-fetch-and-http-client-javascript).

**Q194. Does fetch reject on HTTP 500?** — **Expected:** Normally no; Promise fulfills with Response, so application checks ok/status. **Reasoning:** Network success vs HTTP application status. **Common incorrect:** “catch handles all 4xx/5xx.” **Follow-up:** What failures reject? **Related:** [Browser](../paradigms-patterns-browser.md#56--browser-fetch-and-http-client-javascript).

**Q195. Why use AbortController with fetch?** — **Expected:** To cancel obsolete/timeout/lifecycle-bound request work through signal. **Reasoning:** Promise rejection alone doesn't stop operation. **Common incorrect:** “clearTimeout cancels fetch.” **Follow-up:** Stale response defense too? **Related:** [Browser](../paradigms-patterns-browser.md#56--browser-fetch-and-http-client-javascript).

**Q196. CORS purpose?** — **Expected:** Browser policy controlling script access to cross-origin responses/requests under defined rules; not authentication. **Reasoning:** Server headers + browser enforcement. **Common incorrect:** “CORS blocks attackers from calling API.” **Follow-up:** Why server auth still needed? **Related:** [Browser](../paradigms-patterns-browser.md#56--browser-fetch-and-http-client-javascript).

**Q197. CORS vs CSRF?** — **Expected:** CORS governs cross-origin script access; CSRF abuses ambient credentials to trigger unwanted state changes. **Reasoning:** Different threat models. **Common incorrect:** “Enable CORS to prevent CSRF.” **Follow-up:** Name CSRF mitigations. **Related:** [Security](../paradigms-patterns-browser.md#62--browser-security-for-javascript-developers).

**Q198. Why URL/URLSearchParams over string concatenation?** — **Expected:** Standards-based parsing/resolution/encoding and repeated parameter handling reduce encoding bugs. **Reasoning:** URL syntax complex. **Common incorrect:** “Only prettier syntax.” **Follow-up:** Relative URL base? **Related:** [Browser](../paradigms-patterns-browser.md#57--url-apis).

**Q199. localStorage limitations?** — **Expected:** Synchronous string storage, quota/eviction, origin-scoped, XSS-readable, cross-tab concurrency issues. **Reasoning:** Not database/secret vault. **Common incorrect:** “Encrypted persistent storage.” **Follow-up:** Larger structured alternative? **Related:** [Browser](../paradigms-patterns-browser.md#58--browser-storage).

**Q200. sessionStorage vs localStorage?** — **Expected:** Both synchronous string storage, but sessionStorage has browsing-context/session-scoped lifetime/partition semantics while localStorage persists longer. **Reasoning:** Host storage lifecycle. **Common incorrect:** “sessionStorage is server-side.” **Follow-up:** Cross-tab behavior? **Related:** [Browser](../paradigms-patterns-browser.md#58--browser-storage).

**Q201. setInterval risk?** — **Expected:** Callback duration/drift/lifecycle can overlap conceptually with pending work; recursive timeout often gives explicit wait-after-completion behavior. **Reasoning:** Timer schedule is host queueing, not real-time clock. **Common incorrect:** “Interval executes exactly on cadence regardless of work.” **Follow-up:** Cleanup? **Related:** [Browser](../paradigms-patterns-browser.md#59--browser-timers-and-scheduling).

**Q202. requestAnimationFrame purpose?** — **Expected:** Schedule visual update callback near browser rendering opportunity. **Reasoning:** Coordinate animation with rendering, not generic timer. **Common incorrect:** “Faster setTimeout.” **Follow-up:** Where heavy CPU goes? **Related:** [Browser](../paradigms-patterns-browser.md#59--browser-timers-and-scheduling).

**Q203. What is Web Worker?** — **Expected:** Browser host worker agent executing JS off main UI thread with message/shared-memory communication. **Reasoning:** No direct DOM access. **Common incorrect:** “Async function thread.” **Follow-up:** Best workload? **Related:** [Browser](../paradigms-patterns-browser.md#60--web-workers).

**Q204. Why doesn't Worker need DOM access?** — **Expected:** DOM is main-thread-centric host API; worker isolates computation and communicates results to main thread. **Reasoning:** Avoid concurrent DOM mutation model. **Common incorrect:** “Workers can querySelector if imported.” **Follow-up:** How render worker result? **Related:** [Browser](../paradigms-patterns-browser.md#60--web-workers).

**Q205. Structured clone vs JSON clone?** — **Expected:** Structured clone supports cycles and many structured built-ins/transferables; JSON loses types/undefined/etc and cannot handle cycles. **Reasoning:** Different algorithms/purposes. **Common incorrect:** “Both serialize to text.” **Follow-up:** Can functions clone? **Related:** [Browser](../paradigms-patterns-browser.md#61--structured-clone).

**Q206. What is transferable object?** — **Expected:** Certain objects/resources can have ownership transferred during structured clone/message to avoid copy, often detaching sender view. **Reasoning:** Performance/ownership. **Common incorrect:** “Shared mutable copy.” **Follow-up:** ArrayBuffer example? **Related:** [Browser](../paradigms-patterns-browser.md#61--structured-clone).

## Browser security

**Q207. What is DOM XSS?** — **Expected:** Client-side code places attacker-controlled data into execution-capable DOM sink/context, causing script/code behavior. **Reasoning:** Source→sink flow. **Common incorrect:** “Only server template issue.” **Follow-up:** Safe text sink? **Related:** [Security](../paradigms-patterns-browser.md#62--browser-security-for-javascript-developers).

**Q208. Why avoid eval/Function?** — **Expected:** String-to-code execution increases injection/CSP/audit/optimization risks and usually has safer alternatives. **Reasoning:** Data should stay data. **Common incorrect:** “eval is only bad because slow.” **Follow-up:** Config parser alternative? **Related:** [Security](../paradigms-patterns-browser.md#62--browser-security-for-javascript-developers).

**Q209. What does CSP provide?** — **Expected:** Browser-enforced content/resource execution policy reducing attack surface/impact, especially script injection; not replacement for safe coding. **Reasoning:** Defense in depth. **Common incorrect:** “CSP sanitizes HTML.” **Follow-up:** What are nonces/hashes conceptually? **Related:** [Security](../paradigms-patterns-browser.md#62--browser-security-for-javascript-developers).

**Q210. Why not put server secret in frontend bundle/env?** — **Expected:** Browser-delivered code/data is accessible to users/attackers with page access; client cannot keep server secrets. **Reasoning:** Trust boundary. **Common incorrect:** “Minification hides key.” **Follow-up:** Where should privileged API call occur? **Related:** [Security](../paradigms-patterns-browser.md#62--browser-security-for-javascript-developers).
